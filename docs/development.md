# Development map

Read `AGENTS.md` for the repository's work and publication rules. The README
describes deployment, authentication and the user-facing services. This file is
a navigation guide for making focused changes.

## Where to start

| Change | Implementation | Tests |
| --- | --- | --- |
| Request polling, readiness and admin endpoints | `src/main.ts` | `test/execute.test.ts`, `test/deploy.test.ts` |
| Job execution, source conversations and agent actions | `src/execute.ts`, `src/agent-tools.ts`, `src/github-mcp.mjs` | `test/execute.test.ts`, `test/agent-tools.test.ts` |
| Durable jobs, retry scheduling and quota classification | `src/state.ts` | `test/state.test.ts` |
| Subscription app-server connection and turns | `src/codex.ts` | `test/codex.test.ts` |
| Branch selection and controller publication | `src/workspace.ts` | `test/workspace.test.ts` |
| GitHub App requests, pagination and comments | `src/github.ts` | `test/github.test.ts` |
| Worker status and conversation display | `src/worker.ts`, `src/dashboard.ts`, `web/index.html` | `test/worker.test.ts`, `test/dashboard.test.ts` |
| Static PR preview packaging and reconciliation | `scripts/package-preview.mjs`, `src/previews.ts`, `src/previews-main.ts` | `test/previews.test.ts` |
| Songspot game, catalog selection and saved presets | `web/songspot/` | `test/songspot*.test.ts` |
| Deployment, service wiring and public routes | `scripts/deploy.sh`, `scripts/deploy-entry.sh`, `compose.yaml`, `Caddyfile`, Dockerfiles, `.github/workflows/ci.yaml` | `test/deploy.test.ts`, `test/web.test.ts` |

The `*-main.ts` files configure and start their corresponding services.
`src/main.ts` starts the controller and contains its polling and scheduling loop.
Tests use local fixtures and fake services; the normal test suite does not need
production credentials or a running deployment.

## Edit and verify

Install dependencies with `npm ci` on Node 22.13 or newer. For a focused test run:

```sh
node --import tsx --test --test-name-pattern="quota" test/*.test.ts
```

To run a single test file directly:

```sh
node --import tsx --test test/state.test.ts
```

Before publishing controller changes, run:

```sh
npm run format
npm run format:check
npm run check
npm test
```

Formatting covers `src/`, TypeScript tests and JavaScript build scripts. Web
assets retain their existing formatting. CI enforces the same formatting scope
and also validates Docker images, Caddy and Compose; the README lists the local
Docker commands. Match additional checks to the affected service.

Keep runtime behavior changes separate from formatting where practical. Use
existing fixtures to verify changed behavior, especially interruption recovery,
publication retries and authentication boundaries. Durable SQLite migrations
must be additive and usable by the previous release. Preserve thread IDs and
workspaces across interruptions and quota waits. Deployment must build before
draining, abort on drain timeout and restore the previous release after failed
readiness checks.

## Documentation and generated files

`docs/pr-previews.md` documents the implemented preview service, its limits and
operation; it is linked from the README. Keep service documentation current
when changing the associated code. Do not commit temporary implementation plans
or local execution transcripts.

`preview.json` is generated by `scripts/package-preview.mjs` for CI artifact
upload and is ignored by Git. Dependencies, local credentials and SQLite files
are also ignored. Keep credentials out of source files, fixtures and logs.
